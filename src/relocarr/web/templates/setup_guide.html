Setup Guide

The core risk relocarr exists to manage is two things moving the same files -- the *arr's own import and relocarr's ferry step. Most rows below are also checked live on each app's own Preflight page (Settings → App Config → pick an app); the ones marked one-time are setup steps, not an ongoing setting, so nothing can check them continuously.

Radarr

SettingRequiredWhy
Root folders Only the staging folder (e.g. the path shown on the app's App Config page). Remove any root folder on the destination. Otherwise Radarr still writes to the destination itself.
Existing movies one-time Repoint to the staging root without moving files (Movie Editor → change root folder → "no, I'll move them"). Their stored paths would otherwise still point at the destination.
Collections and Import Lists one-time Repoint each one's own Root Folder field too (Movies → Collections, and Settings → Import Lists) -- they store it separately from individual movies. A removed destination root folder leaves these pointing at a now-missing path.
Download Client → Completed Download Handling (global, above the client list) On Unrelated to relocarr itself, but required for Radarr to ever notice a finished download at all.
Connect → Webhook Add one: the URL and X-Relocarr-Token header shown on the app's detail page, method POST, On Import + On Upgrade enabled. The trigger relocarr needs.
Connect → Plex / Jellyfin / Emby All triggers disabled They'd scan the staging path, which the media server can't see.
Download client → Remove Completed Downloads Off relocarr removes the torrent itself -- leaving this on collides with that cleanup.
Media Management → Recycle Bin Empty Otherwise API deletes fill the recycle bin instead of freeing staging.
Media Management → Use Hardlinks instead of Copy On Instant import, no extra space -- requires staging and downloads on the same mount.
Media Management → Rename Movies On The naming format is the only source of the destination filename.
Import Extra Files Extensions match relocarr's sidecar list (Settings → General) Sidecars are only copied if the *arr imported them in the first place.

Even with the Webhook connected correctly, a single delivery can still be lost -- confirmed live, 2026-10-25: Radarr doesn't retry a failed webhook send, so one landing during a relocarr restart leaves that import fully done on Radarr's side but completely untracked by relocarr, with nothing to notice on its own. Check Queue → Find & trigger missed transfers to target folder (i.e. your Plex library) occasionally, especially right after restarting relocarr, to catch anything the webhook missed.

Sonarr

Same table as Radarr, with the TV staging folder and Rename Episodes instead, plus:

SettingRequiredWhy
Media Management → Season Folder Format one-time Must produce the same folder names the destination already uses relocarr copies Sonarr's path as-is -- a mismatch creates duplicate season folders.
Media Management → Series Folder Format / per-show path one-time Folder name identical to the existing destination folder A mismatch creates a duplicate series folder next to the real one.
Series → Season Folders On for every series Season subfolders are mandatory in the preserve layout Sonarr always uses.

Layout mode is locked to preserve for Sonarr in relocarr -- there's no "flat" option to pick by mistake.

Transmission

SettingRequiredWhy
RPC reachability Relocarr's container must be able to reach Transmission's RPC host:port (same Docker network, or the right host/port otherwise). Every seal/stop/remove action goes through this. No other Transmission setting matters if this doesn't work.
RPC authentication If Transmission requires a username/password, enter the same ones in that app's Download Client config in relocarr. relocarr authenticates the same way any other RPC client would.
"Stop seeding at ratio/idle" (Transmission's own setting) Not required either way -- independent of relocarr relocarr stops a torrent itself as soon as it's complete and tracked in the *arr's queue (the SEALED step). Relying on Transmission's own limit instead can race: if Transmission removes a torrent before relocarr ever sees it in the queue, relocarr never gets the chance to seal/clean it up itself.
Category per *arr instance Recommended, not required by relocarr relocarr doesn't filter by category -- this just keeps the *arr's own download routing tidy.

Shared

  • relocarr's container must mount the download folder, staging folder, and destination at the same paths as the *arr and Transmission containers -- v0.1 has no path mapping.
  • Staging must not be inside the destination or vice versa; relocarr refuses to compute a path otherwise.
  • Nothing else may write to the staging root. relocarr only ever deletes inside it, never above it.
